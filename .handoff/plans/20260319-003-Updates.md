## Roadmap Overview

This document defines all implementation sprints for Phase 2 of the metadexer project. Phase 2 delivers a working local-mode system where `metadexer ingest <directory>` indexes files, stores bytes in a local vault, and commits metadata to a catalog with basic query support (§22.1).

**Phase 2 scope:**

- Vault module: put, get, head, verify for file-based content. put_inline, get_inline for small text-based content. Local filesystem backend first. S3-compatible backend second. Inline database surface co-located with the catalog database.
- Catalog module: IndexEntry ingest, field projection, basic search (MIME type, size, timestamps, name, extension). Full-text search indexing of vault-stored inline content. PostgreSQL backend as primary target. SQLite backend for portable/evaluation use.
- Basic sync pipeline: index, route, store, catalog. Enough for `metadexer ingest` to work end-to-end.
- CLI wiring: `ingest`, `search`, `vault verify`, `config` subcommands.

**Deferred to later phases:** reference tracking, temporal correlation, reconciliation, pruning (Phase 4), Sync Plan dry-run, resumable pipeline (Phase 3).

**Key architectural principle:** The vault is the sole owner of all stored content, both file-based (local/S3) and inline text. The catalog stores metadata and search indexes but never persists content. The sync module decides which vault surface receives content but never stores or indexes it directly. This clean separation ensures that future features (multi-vault replication, P2P sync, federated deployments) can treat the vault as a self-contained storage unit without reasoning about content scattered across module boundaries. See §3.2 and §5.1 for the full rationale.

#### 4.1. config.py

Create `src/metadexer/config.py` implementing the full configuration architecture described in §13.

**Dataclass hierarchy (all frozen):**

```python
from dataclasses import dataclass, field
from pathlib import Path


@dataclass(frozen=True)
class S3Config:
    endpoint_url: str = ""
    bucket: str = ""
    prefix: str = ""
    region: str = ""


@dataclass(frozen=True)
class VaultConfig:
    backend: str = "local"
    root: str = ""
    chunk_size_bytes: int = 8_388_608
    s3: S3Config = field(default_factory=S3Config)


@dataclass(frozen=True)
class SqliteConfig:
    path: str = ""


@dataclass(frozen=True)
class PostgresConfig:
    host: str = "localhost"
    port: int = 5432
    dbname: str = "metadexer"


@dataclass(frozen=True)
class CatalogConfig:
    backend: str = "sqlite"
    sqlite: SqliteConfig = field(default_factory=SqliteConfig)
    postgres: PostgresConfig = field(default_factory=PostgresConfig)


@dataclass(frozen=True)
class StorageRoutingConfig:
    inline_max_bytes: int = 65_536
    inline_mime_prefixes: tuple[str, ...] = ("text/",)
    inline_extra_types: tuple[str, ...] = ("application/json",)


@dataclass(frozen=True)
class LoggingConfig:
    level: str = "INFO"
    file_enabled: bool = False


@dataclass(frozen=True)
class MetadexerConfig:
    vault: VaultConfig = field(default_factory=VaultConfig)
    catalog: CatalogConfig = field(default_factory=CatalogConfig)
    storage_routing: StorageRoutingConfig = field(default_factory=StorageRoutingConfig)
    logging: LoggingConfig = field(default_factory=LoggingConfig)
```

Default values match §13.3 exactly. Use `tuple` (not `list`) for sequence fields in frozen dataclasses to maintain immutability.

**Functions to implement:**

1. `get_app_data_dir() -> Path` — Returns the platform-specific application data directory per §13.2. Uses `os.environ` and `sys.platform` for detection. Creates the directory if it does not exist.

2. `load_config(project_dir: Path | None = None, cli_overrides: dict | None = None) -> MetadexerConfig` — Implements the four-layer override chain from §13.1:
   - Layer 1: Compiled defaults (the dataclass defaults above).
   - Layer 2: User config file at `<app_data_dir>/config.toml`, if it exists.
   - Layer 3: Project-local config at `<project_dir>/.metadexer.toml`, if `project_dir` is provided and the file exists. If `project_dir` is None, search upward from the current working directory for `.metadexer.toml` (stop at filesystem root).
   - Layer 4: `cli_overrides` dict, if provided.
   - Merge layers using a recursive dict merge. Convert the final merged dict to `MetadexerConfig` using `_dict_to_config()`.
   - Unknown keys in TOML files are silently ignored (§13.1).
   - Parse TOML using `tomllib` (stdlib, Python 3.11+).

3. `_dict_to_config(data: dict) -> MetadexerConfig` — Recursively constructs the frozen dataclass hierarchy from a plain dict. Handles type coercion for known fields (e.g., list to tuple for sequence fields). Ignores unknown keys.

4. `_merge_dicts(base: dict, override: dict) -> dict` — Recursive dict merge. Override values replace base values for scalar keys. For nested dicts (TOML tables), merge recursively. For list/tuple values, override replaces entirely (no concatenation).

Raise `ConfigurationError` (from Item 1) when a TOML file exists but contains syntax errors.

Add a module-level `__all__` exporting all public classes and `load_config`, `get_app_data_dir`.

### 4. Work Item 2 — Local Filesystem Backend

**Goal:** Implement the local filesystem vault backend in `vault/backends/local.py` per §5.3 and §5.4.1.

**Affected files:**

- `src/metadexer/vault/backends/local.py` (rewrite from stub)

#### 4.1. Implementation

Replace the stub with a class `LocalVaultBackend(VaultBackend)` that stores objects on the local filesystem using the two-character prefix sharding scheme from §5.3.

**Constructor:** `__init__(self, root: Path, chunk_size: int = 8_388_608) -> None`
- `root` is the vault root directory. Store it as a resolved `Path`.
- `chunk_size` is the buffer size for chunked I/O.
- Create the `root` directory (and parents) if it does not exist.

**Helper:** `_object_path(self, storage_name: str) -> Path`
- Returns `root / storage_name[:2].lower() / storage_name`.

**Path validation:** Before any I/O operation, validate that `storage_name` does not contain path separators, is not empty, and has at least two characters. Raise `VaultIOError` on validation failure (§20.1).

**Methods (all per §5.4.1 contracts):**

- `put(storage_name, source)`: Create the prefix directory if needed. Copy `source` to the object path using chunked reads/writes of `chunk_size` bytes.
- `get(storage_name, destination)`: Copy the object to `destination` using chunked I/O. Raise `VaultObjectNotFoundError` if the object does not exist.
- `head(storage_name)`: Return `self._object_path(storage_name).exists()`.
- `delete(storage_name)`: Unlink the object file. Raise `VaultObjectNotFoundError` if it does not exist.
- `open_read(storage_name)`: Return `open(self._object_path(storage_name), "rb")` as a context manager. Raise `VaultObjectNotFoundError` if the file does not exist.
- `iter_storage_names()`: Walk the vault root, yield `file.name` for every file found under prefix directories. Yield in sorted order.

Wrap OS-level errors in `VaultIOError` using `raise ... from ...` per §9.3.2, except for the missing-file case which uses `VaultObjectNotFoundError`.

### 5. Work Item 3 — Pipeline Orchestrator

**Goal:** Implement the basic ingest pipeline per §7.2.

**Affected files:**

- `src/metadexer/sync/pipeline.py` (rewrite from stub)

#### 5.1. Implementation

The critical data flow for inline-routed content:
1. Sync reads file content as UTF-8.
2. Sync stores it in the vault: `vault.put_inline(storage_name, text_content)`.
3. Sync passes the same text to the catalog: `ingestor.ingest(raw_entry, "inline", search_text=text_content)`.
4. The catalog builds its FTS index from `search_text` but does not persist it.

For file-routed content:
1. Sync stores bytes in the vault: `vault.put(storage_name, source_path)`.
2. Sync commits metadata: `ingestor.ingest(raw_entry, "vault", search_text=None)`.

```python
@dataclass(frozen=True)
class SyncResult:
    indexed: int
    new_vault: int
    new_inline: int

    failed: int
    errors: tuple[tuple[str, str], ...]
```
